# Deskfront 赛事解说

## 2026-10-15：安妮 · 桌面小导演 / 体验讲述

当前定位为玩具桌面的小主人，表达现有体验分析与生成链路的安排。人物不额外决定关卡，不给士兵下令。下面旧版“只介绍已建成关卡、不读未来计划”的范围由本节扩展；战斗短句与弹幕仍使用原公开战况边界。

- `presenter-experience.ts` 从同一 RuntimeSnapshot 的原生 observation 与 `payload.game.worldDirector` 生成只读投影，核对 run、instance、关号和 operation。当前关设计取已完成生成记录中冻结的 `experience_basis` 和实际选定意图；后续安排取本关有效分析报告；复盘保留模型判断与原生结果的区别。无数据就缺省，不另发分析或生成请求。
- 生成前的原目标、策划实际选择、未采用／调整、固定演示规则、待建成方案分别标注。关中观察带采样范围，不能概括为整关结论；历史无真人反馈时不宣称玩家体验已改善。
- 保留 `director_intro`、`battle_commentary`、`director_reflection`，增加 `director_plan`（后续体验安排）、`director_revision`（新旧安排的取舍）、`director_review`（期待与反馈）。关键战损仍优先；新计划先于普通复盘，避免不断更新的复盘挤掉未来安排。
- 战况保持8—38字；设计说明通常两三句、45—90字，硬上限96字，给原生110字符字幕和表情留空间。信息不足允许短说或留白；不靠增加术语或逐项报配置凑长度。
- 设计事件在上句原生播放结束后至少留白4秒；普通战况12秒、重要战况5秒。CD只是最大频率，不到点自动说话。语义内容相同的报告刷新不再触发；模型主动留白也消费该版本。A→B→A仍算相对上次已播计划的调整。
- 战况仍用短有效期；设计台词的准备窗口为25秒，期间检查真实关卡身份与计划版本。计划替换会撤回尚未播出的旧文案和语音；有效长说明在同关 active→completed 时可讲完，换关、换局或暂停仍停止。音频不重叠，播音期间持续收集事件。
- 请求、台词与原生开播保留 `presentationRole`、`narrationKey` 及报告/operation来源；无效候选记录限定长度的原文、引用与失败环节，供后续改进，不用预写台词替代模型。

验证见 `output/experience-presenter-20261015/`：93项相关回归、真实存档投影核对及真实文字/TTS样本。假后端测试验证调度与边界，不代表整局实机听感验收；当前录音是历史证据驱动的试讲，不是新一局运行录像。

## 2026-10-15：小导演兼解说（本轮扩展前）

保留当前 Annie 角色模型、透明人物、字幕位置与现有女声音色，将角色定位统一为“玩具桌面的小主人，一个爱摆玩具兵的小女孩，兼任小导演和解说”。文本生成、JEV 表情动作选择、支持 context_texts 的 TTS 共用这一人设；不使用刻意捏嗓、婴儿叠词或成熟女主播口吻。女声音色不等于已验收的儿童听感，仍需用户试听。

- `director_intro`：从同一原生快照读取当前已建成关卡的任务、真实部署、在场兵种及已建成路线，选一项安排用第一人称介绍。已播回执确认后，每关只介绍一次；新运行、关卡或构建 operation 使用独立身份。重要伤亡与显著消耗优先转为战斗解说。
- `battle_commentary`：沿用真实战况和跨关历史，跟随变化反应；关卡配置不当作战斗成果，人物不发战斗命令。
- `director_reflection`：引擎确认当前任务完成时，按实际结果回顾。不自动许诺下一关的任务、兵种或结局。

当前接入的是已建成关卡的安排介绍，还没有搭建途中对白或让人物自行发出改关命令。关卡生成继续由现有 DeepSeek/JEV 链路完成。`presenter-context.ts` 排除未来计划、候选槽位和不匹配的旧回执；原来的公开战况过滤保持。介绍必须引用当前导演事实，另拒绝明显的虚构路线、本人指挥、营救成功和炮手人数转为炮数量等错误。规则不是完整语义证明，仍需要实际对局抽查。

保存对局 `output/tactical-icons-20261015/live/state.json` 的真实文字模型及 TTS 试验在 `output/child-director-20261015/`。前两轮数量误写样本保留为 `*-first`、`*-second`；修正后的最终样本为 `model-probe.json` 与 `sample.mp3`。这是记录快照试生成及合成，未代替原生游戏窗口播放与整场观感验收。

## Open Annie 原生主播（2026-10-12）

用户确认的入口是独立 EXE。2026-10-12 布局修正：保留游戏原来的底部字幕，人物半身像紧贴字幕左边，在解说前出场、说完后停留2秒。去掉右下角卡片、标题、按钮和重复字幕。公开 Harness 的 `tools/deskfront-attach.ts` 在真实 AI 观战开启时，启动 `DeskfrontAnnieHost.exe`。它识别 SDK 启动器的实际 `DeskfrontGame.exe` 子进程，将 WebView2 窗口设为游戏 HWND 的原生子窗口，关闭游戏时退出。`--annie false` 只关闭主播，`--spectator false` 同时关闭主播、解说与弹幕。离线游戏和 mock 不自动请求主播模型。

链路：引擎事实 → 现有 DeepSeek 解说 → 豆包 MP3 → Godot 播放回执 → Annie。WebView 不重复播放声音，只解码同一句 MP3，以原生播放器的剩余时长驱动原项目音量／频带口型。字幕仍由原生解说层完整显示。发行版v17增加 `subtitle_rect`／`viewport_size` 只读坐标，主播据此对齐字幕；旧版按原字幕最大宽度兼容定位，短句无法保证完全贴合。原生播放器收到暂停／结束回执后，主播停止说话并隐藏；400ms状态同步、1600ms失联截止意味着同步不是采样级精确同步。

JEV 只收到当前解说、已有解说情绪、最多六条事实及观察时间；不收到地图、控制工具或密钥。输出三项离散选择：已安装的表情、已安装手势或 none、gentle/moderate/high 强度。每个解说 ID 最多请求一次，默认每局最多40次，1800ms 截止；新句子替换旧句子时取消旧请求，不执行过期结果。无解说时不增加动作请求；页面失联超过8秒停止模型调用。模型失败记录明确状态，字幕期间保留自然说话动作，不伪造 JEV 选择。实际费用还取决于服务计费，尚未做成本基准。

角色、动作与脸部平滑沿用 [Open Annie](https://github.com/rehan-remade/open-annie)，固定版本 `1a3aebfe32343b119263c8b7eba3b7cb1d4e4507`。没有接入其 GPT-Live-1 WebRTC 语音链路，改为复用本项目已工作的解说／TTS；没有继承其 confidence 门槛。源码 Apache-2.0、动作包 CC0、默认 VRoid 示例角色适用独立许可，原始 LICENSE、NOTICE、avatar.json 和资产说明一起保留。当前本地配置已使用用户指定的成熟温柔女声（ICL_uranus_zh_female_chengshuwenrou_tob），真实seed-tts-2.0合成成功。API Key仅保存在被忽略的.env，公开包不含密钥。

构建：`python scripts/build-deskfront-presenter.py`。需要 Windows x64、.NET Framework 4.6.2+ 和 Edge WebView2 Runtime；脚本校验固定 SDK 包 SHA256。主播依赖本地 Harness 服务，单独双击游戏 EXE 仍是离线算法版。角色30fps上限、像素比上限2、禁用动态阴影；原生透明合成最多20fps、仅一帧在途，使用预乘Alpha与UpdateLayeredWindow，空白像素透明且发丝边缘保留部分透明。只传人物小画面，不捕获或重传整局游戏画面；尚未做整机帧率基准或干净 Windows 机器安装验收。

可观察证据：`logs/annie/<会话>.jsonl` 记录实际模型请求／决定，`logs/annie/<会话>/host.jsonl` 记录父子 HWND、角色加载、执行的表情／动作及实际播放中的口型帧。该目录内的 PNG 是 WebView2 CapturePreview 生成的真实渲染截图；它证明主播画面，不代表整局游戏画面验收。

当前机制（2026-10-08）：程序选择触发时机，所有解说正文交给真实文字模型；伤亡与过关也不再绕过模型直念通知。模型失败时记录失败原因、短暂退避并显示服务状态，不生成程序代写的解说。下文较早的“伤亡直达播报”记录仅描述历史实现。

每局维护独立的跨关卡事实历史：引擎确认的关卡结果、阵亡、装备入场／发射／接管、炮组人数变化、多人实际转移与行进受阻。历史采集不受语音正在播放影响，最多保留96条过程事件、12段关卡结果；每次提供最近24条关键历史和16条确认开始播放的解说。已播内容用于接话，不作为战况证据。普通模式同样提供真实坦克和迫击炮事实；剧情仅额外提供叙事意图。

播报按事件触发，并在平缓期最多每30秒邀请模型回顾已有局面；模型可选择留白。2026-10-09修正：上一句收到原生播放结束回执后，普通变化至少留白12秒，阵亡等重大变化至少留白5秒，再请求新的解说；这些都是现实时间，不随游戏加速缩短。播放中持续收集事实，但不预生成下一句，避免8秒有效期的文案在留白期间过期。

首次装备开火仍可触发介绍，后续常规坦克／迫击炮发射和方向不明的换位继续记入事实历史，但不单独触发新段；重大变化和30秒回顾仍可使用这些事实。加强近似换词复读过滤。士兵阵亡不再自动截断一句正在播放的解说。暂停、关卡／运行实例变化和过期内容仍取消。下文连续预取等记录属于旧版；当前时序以本段为准。

保留解说小明音色。TTS 2.0的`additions.context_texts`接收文字模型选择的语气（紧张、惋惜、兴奋等），与正文分开传递，不把语音指令读出来。参考[火山官方语音指令文档](https://docs.volcengine.com/docs/DoubaoVoice/WebSocketBidirectionalStreaming-V3?lang=zh)。语气参数传递与听感验收是不同证据。


## 用词与复读修正（2026-10-08）

队伍位移按数秒实际位置变化提供方向证据：至少两名成员明显接近本关交战目标时标为推进，明显远离时标为后撤，只有横向变化时只标换位；不从移动或路线推断已绕后、突破成功。模型使用推进、后撤、换位或有证据的绕侧尝试，不用“挪步”“体量”“整体位移”等填空。事实中的证据限制用于约束写作，不逐句念成免责声明。

发布时过滤上述抽象套话，并比较最近已播放文本的字符相似度，拦截近似换词复读；明确数字变化保留为可能的新事实。拦截后不生成规则文案，不调用语音，以留白和下一次模型判断处理。真实听感仍需通过新对局验收。

## 当前版本：宏观走势与克制的情绪（2026-09-28）

用户最新偏好覆盖下面旧版连续动作播报规则：字幕更小，黑底更小；关注宏观和情绪，不逐个报换弹、受击。Godot 字号16–20px（1280宽约18px），底板随文字宽度收缩，上限62%画面宽，内边距12×6px，不透明度72%；网页字幕15px、底板随字收缩。

在调用模型之前筛选队伍层面的变化：开场、明确减员、相对上次叙述全队平均血量下降至少25个百分点、任务完成。普通开火、换弹、进出掩体和轻微受伤不触发，也不传给宏观文案生成。无明显变化不调用模型、不合成语音，允许留白；普通分析至少间隔10秒，关键转折可提前响应。25个百分点与10秒是本项目初始参数，不是赛事行业标准。

情绪建立在真实意义上：开场克制，明显消耗表达紧张，最后一人突出悬念，阶段拿下表达释然。不能从人数优势推断必胜、从掉血推断战术失败，也不能编造士兵心理。现在调整的是内容选择与文本表达，没有新增语音服务的情绪控制参数。地形控制、战线推进与战略逆转尚未建立可靠的宏观指标，不宣称已识别。

参考：[Drury谈比赛与解说的关系](https://thesetpieces.com/interviews/peter-drury-ive-always-had-a-fascination-with-words-language-plays-into-the-story-as-well/)强调观众为比赛而来，也承认过度多言的缺点；[2024访谈](https://worldfootballindex.com/2024/08/peter-drury-on-the-art-of-commentary-and-calling-footballs-biggest-matches/)强调关键瞬间的意义与情绪强弱要结合整场背景。

以下连续播报链路和历次记录保留用于说明演进，冲突处以本节为准。


入口：`http://127.0.0.1:3777/runtime/deskfront`。AI 观战新局默认开启解说，可调音量或随时关闭；旧对局和已结束对局不会重新生成。当前仅支持 AI/规则控制的全场观战，真人会话拒绝生成，避免泄露视野外敌情。即使战斗使用 mock，开启解说仍会调用真实文字模型和语音服务。

## 当前链路

服务端读取真实引擎快照 → 事实变化与当前局势 → DeepSeek 连续中文解说 → 豆包语音 → Godot 原生播放器与游戏底部字幕。观察台同步显示正在播放的字幕。浏览器不再播放第二份声音。

文字模型复用 Harness 的后端工厂、请求管理与超时取消；commentary 角色使用已有 DeepSeek 凭证与模型，单独设置非思考、180 token 短输出，OpenRouter 使用 throughput 路由。JSON 请求支持解说专用系统角色，原战术指挥默认提示和思考配置不变。语音凭证从被 Git 忽略的 `.env` 读取，不传给浏览器。音色由私有配置 `DOUBAO_TTS_SPEAKER` 指定；当前按用户要求使用成熟温柔女声，资源为 `seed-tts-2.0`。

解说是只读消费者，不改变战斗目标、IntentExecutor、引擎状态或模型控制权。

开启剧情引导后，解说只收到独立的叙事风格目标 `narrative_reference.presentation_goal`，不收到剧本正文。预设／自定义剧本仍提供给战术与生成模型，观战模型无法从它获知第二关坦克、夺炮安排或预定结局。当前战况与跨关卡引擎历史是唯一事实来源；准备场地时不播报关卡进展。正文由模型生成，发布前过滤引用无关事实预告后续关卡或未观察装备的明显错误。普通版不传风格字段，同样保留真实战况历史。

普通版和剧情版都观察真实装备状态：坦克存在与血量归零、迫击炮控制权与实际接管、实际发射炮弹、炸药包投出或爆炸。单位卸载不算击毁，接管进度不算已接管，投出和发射不算命中，换关不把旧状态算作新事件。事实 ID 校验不能保证每句话语义绝对准确，观感与语义准确性仍需真实对局验收。

## 内容与时序

- 目前使用存活人数、明确血量归零、受伤、最近真实开火、卧倒、明显位移和本段任务完成。
- 单位从快照消失不等于死亡；跨局/跨区重新建立基线，不将卸载计作击杀。命令接受、计划和移动意图不作为动作完成证据。
- 连续解说交替跟进实际动作、比较当前局势，并承接最近四段文案；平稳时段也可生成，不依赖击杀等大事件。每段目标18–32字、最多两个短句，只讲一个重点。
- 当前段剩余3秒内准备下一段，最多一个请求在途、一个结果待播。游戏回执确认上一段结束后才播放下一段，避免叠音。3秒是本项目调度参数，不是足球解说行业标准。
- 每局文字、语音各最多600次尝试，关闭再开启不重置额度。用完后停止生成，战斗继续。
- 连续解说文字超时3秒，语音请求上限12秒，但整条内容自观察起8秒过期并取消在途请求。暂停、结束、换局、区域变化和存活名单变化丢弃旧结果；关键变化会中断旧播报。
- 服务器驱动连续播放。切到游戏、隐藏或关闭观察台不停止；手动关闭解说、暂停游戏或对局结束才停止。旧对局没有字幕层，需要重新开局；未收到原生就绪回执不会调用模型或语音。
- 字幕与整段声音同时显示、随声音结束消失；目前是段落同步，不是逐字卡拉OK。语音失败则按阅读时间显示文字。
- 模型无有效输出时标注「事实播报」，语音失败保留字幕，不把兜底包装成AI生成。
- 返回必须引用本批事实ID；这是结构和引用校验，不是完整语义事实核验，仍需人工抽查模型是否过度推断。

本版使用 HTTP 流式接收音频，收齐后交 Godot 解码，利用提前准备衔接下一段，尚未实现边合成边播放。`firstAudioMs` 仅表示服务端收到首个音频分片，不是用户听见声音的时刻。每条记录分开保存文字耗时、语音首包和完整音频耗时。

## 证据与限制

记录位于 `logs/commentary/<session>.jsonl`，包含原始事实、文案、来源、观察时间、请求次数与耗时；不含密钥。对局状态和战斗记录仍沿用原有会话日志。服务端保留当前/下一段音频与最近8条已播放字幕。对局目录的 commentary-command.json、commentary.mp3 和 commentary-status.json 是原生播放桥；真实开播、结束、字幕可见和音频播放状态另有日志回执。重开页面可恢复服务端历史。未实现赛后长复盘或悬念状态机。
