# Deskfront 文件堡垒解救遭遇

“堡垒”是桌面文具临时围出的防御点：入口两侧竖放彩色活页夹，两边和后方叠放 A4 文件与夹板，外围再放两叠便签纸。它们都是可破坏掩体，并非真实军事建筑。该场景叠加在无尽推进的 3×3 桌面区域图上，入口、外围守军和被困队员都由同一份配方约束。

## 玩法

- 第一关即可选择营救（内部 `revision=0`，从零计数）。之后队伍仍须有空位，且距离上次营救至少三段；这是开放选项，不保证每到三段必出现。空间搭建员从经连通性验证的区域图和文具组合中选择。
- 引擎在区域施工完成后生成文件夹围墙、入口外围守军和一名 `captive` 绿色队员。队员可见，但获救前不移动、不射击、不计入可战斗小队；为他预留第六个队伍席位。
- 清除本段外围守军后，队员转为 `active`，加入绿色小队，控制纪元更新以便 Harness 重新编队。任务回执记载 `mission_kind`、`captive_id`、`rescue_status` 与新增队员数。
- 文件夹墙有 240 HP；射线和路径查询使用真实掩体，摧毁后由引擎重建通路。普通遭遇仍按原规则执行。

## 验证边界

`rescue_contract.gd` 在真正的 Godot 引擎中检查生成、射线阻挡、可达性、破坏、解救加入及防重复加入。`rescue_visual.gd` 生成前后画面供人工检查文具辨识度。静态通路检查不等于实战能稳定攻下；实际胜率和拟人表现需要在持续对局里观察。
