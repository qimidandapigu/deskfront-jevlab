# 请求调度去重

针对上一局 240 次请求中大量维持命令的现象，本轮修改：

- 同兵 participation_gap 按原因及最近真实进展分组，重复条件 8 游戏秒内合并。原因改变或取得新进展后再次失败可立即通知。
- 小队定时复核到期、没有待处理新事件、引擎命令匹配当前计划，且所有存活成员最近 5 秒都有测量进展时，延后一次例行确认。
- 进展沿用实际距离缩短、射击、首次获得掩体等记录；仅有路线或保护姿态不算进展。
- 危险事件仍沿用原触发机制，不等待 8 秒。引擎即时避险没有改动。战略及个人调用机制没有在本轮删除。

验证：小队 Harness 46、个人 Harness 10 项通过。新增检查覆盖有效执行免复核、危险立即唤醒、无进展恢复复核、重复受阻合并及原因变化唤醒。

尚未进行新一局真实模型对比，不宣称调用下降比例。旧会话不会热加载修改。此为调度精简，不能解决没有可执行站位或引擎低帧率本身。
