# 单兵停滞与身份上下文修复（2026-09-21）

## 已确认的缺陷

- 原生 `observation()` 精简视图未包含 `navigation_revision`。单兵路径使用该视图读取带地图版本的空间报告，`read_queries()` 将报告误判为地图不匹配并返回空对象。开场指挥使用完整快照，因此开场正常不能证明单兵工具可用。
- 进展统计用“当前敌我距离缩短”作为推进收益，敌人走近也会清零本兵停滞计时。
- `immediate` 任务每帧刷新 `granted_at`，没有保留真实开始时间。
- 单兵问题覆盖了详细执行指令；身份只藏在问题键及全队列表中。路线短名单在不同职责下都优先目标区。

## 修复

- Harness 自有观测适配保留地图版本和原生掩体循环字段，仍拒绝过期、位移过大及地图版本改变的查询。
- 推进收益对同一敌方快照比较本兵前后位置；敌方位移不产生本兵收益。立即任务保留开始时间。
- 每个单兵请求明确 `self_id`、`controlled_unit_ids`、本兵编号/阵营/武器，以及执行者、支援对象、攻击对象、启动条件。问题保留完整执行说明，输出仍只能应用到对应本兵。
- 指挥任务根据任务键绑定 `actor_id`；明确区分 `support_for` 与同步伙伴。有存活敌人的支援任务必须指定攻击目标或受支援队友，错误编号拒绝。
- 支援/消灭/侧击职责优先展示指定敌人的已查询射位及参考区；占点职责仍优先目标区。排序不是安全承诺，也不强制侧击。

- 旧局 `deskfront-c399d812-2f1f-4b65-9921-cd7a06234d36` 同一组保存快照重放：三兵各恢复读取 9～10 个导航短步、5 个射位。
- 真实 OpenRouter JEV / DeepSeek 局 `deskfront-c2d148d4-6b2d-41fb-9b78-130b87d20e10`：112 条唯一单兵请求均有正确本人编号；87 条含有效空间结果，25 条仍因新鲜度等条件显示 unknown。
