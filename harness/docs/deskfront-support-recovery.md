# 掩护、推进与避险恢复

本轮修复实际执行问题，不增加模型层级。

## 原因与改动

- 旧掩护判断把近期射击和当前可选目标拼接起来，未核对实际射击目标。现在要求最近实际射击的是机动兵当前面对的威胁，并重新验证该目标射界；正在自保的士兵不计作掩护。这个信号表示实际掩护火力，不代表敌人已被压制。
- 等待掩护超过 5 秒后，旧分支会在尝试推进前返回。现在检测掩护从不可用变为可用，重置等待时钟，允许原任务再次尝试，同时通过 support_restored 通知小队 Jev；不会仅因恢复而唤醒战略重规划。
- 普通机动与试探机动统一在即时危险下中断，保留引擎避险路线的优先权。
- 有掩护的交替推进不再选择火箭、炮或明确分配 fire_support 的成员做突击手。这不是完整的后排站位系统。
- 重复的推进选路和掩体搜索增加 0.8 游戏秒间隔。地形变化、掩护恢复可提前重查；正在移动者的安全检查在限频之前执行。

- 引擎小队合同 61 项通过，新增 8 项涵盖错误目标、实际掩护、避险人员排除、超时恢复、机动放行、危险打断、搜索限频和后方支援不突击。
