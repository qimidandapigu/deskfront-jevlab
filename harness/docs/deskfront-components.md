# 当前实现：统一战斗控制器与组件关卡构建

本页中的模块边界遵循 [所有权与模块化边界](deskfront-ownership-boundary.md)：原生游戏机制以用户在 deskfront-jevlab 中的改动为事实源，Harness 负责控制、观察和 staging 装配。

## 一套控制器

固定 3v5 和生成 3v3 都实例化 `tactics.CoordinatedController`。已移除 `world/combat.py` 的专用控制器；`scenario.py` 只把场景转成任务数据，包括目标、路线和守军，不做模型决策。地图、人数、完成条件可以不同，指挥、执行、反馈与任务进度只有一套逻辑。

DeepSeek 选择策略和整队分工方案（路线不重复占用，或选择自由接敌）。Harness 保存每人路线及节点进度；实际到达节点才推进进度，相同分工重评不会重置进度。JEV 根据任务选择推进、交火或自保，路线变化由指挥重评。生成新段时更新控制版本以拒绝旧命令。模型未返回初始指挥前不启动无计划的单兵调用。

生成模式同时接入原有 `execution_validation.gd` 和 `guarded_unit.gd`：移动前查询原生可达性，射线阻挡反馈与安全恢复规则和三路前哨共用源文件。原始游戏仓库不修改，每局复制并扩展运行副本。

## JEV 选择组件组合

`world/catalog.py` 是组件与位置槽的唯一规格来源，生成给 Godot 的 `world-components.json`。JEV 在一次请求内选择五个字段：

| 字段 | 选择 | 实际影响 |
|---|---|---|
| structure | 隘口 / 错列防线 / 开放庭院 | 遮挡组件尺寸和位置槽 |
| side | 上侧 / 下侧 | 布局、路线与侧翼守军镜像 |
| props | 书堆 / 木箱 | 组件外观及真实遮挡高度 |
| defense | 交叉 / 纵深 | 三名守军的前后分布 |
| position | 内侧 / 外侧 | 遮挡靠中或外移，改变中央可视空间 |

目前为 48 个组合，属于三种预设计结构的参数组合，不是 48 张独立设计的关卡，也不是任意几何生成。道具数和部队数仍固定，后续扩展组件规格即可，不需要增加战斗控制器。

DeepSeek 先读取真实战况与构建历史，选择节奏阶段和五项强度。Harness 平滑后过滤候选：休整高优先纵深阵位，压力高开放交叉阵位，教学/扩展高采用外侧槽，新鲜度高避免重复道具，并尽量避免连续重复结构。随后 JEV 在候选内选择组合。没有真实玩家操作证据时只调观战节奏，不声称建立了技能画像。

Godot 在启动时过滤布局边界、组件重叠、守军部署和双路线连通性；施工前及提交前再次检查单位占用。3 秒构建期间有地形与守军预览，完成后统一激活并回执。失败不会计为建成。下一段仍需本段完成后解锁，暂无无界卸载。

## 场景与验证

旧炮台、楼梯、占旗战场已替换为窄出发区；每段依旧三名守军，绿色开场三人。截图为真实 Godot 静态构建导出，不是模型绘图。

无限生成模式双方步兵的初始及最大血量统一为 50，后续守军和步兵增援复用同一配置；武器伤害、射速、掩体耐久不变。本段守军全部清除且绿色仍有人存活，即完成本段并解锁生成，不再要求出口集合。配置仅注入会话副本的无限模式，不修改原游戏或固定对战模式。新会话加载生效。

生成导演按事件调用：开局及本段完成后各分析一次，再由 JEV 选择组合。每秒采集状态，DeepSeek 读取最近最多 12 次采样；采样不调用模型。上一轮生成请求结束后有 8 秒冷却，正常战斗通常已覆盖冷却；模型返回后还有 3 秒施工预览。不是每 8 秒固定调用模型，也不在交战期间持续重新设计关卡。

- 48 个组合的几何与连通检查通过：`output/world-components-check/catalog.log`。
- 41 项构建合约、7 项控制权限、113 项战斗语义通过；28 项共享战术、6 项场景/持续任务、10 项导演检查通过。
- 离线实机：`output/world-harness-1789907196280/report.json`，确认生成、3v3、绿色命令回执和绕侧节点实际进度。原协同模式实机回执也通过。
- 真实双模型：`output/world-components-check/real-report.json`。组合为错列防线/上侧/书堆/纵深/外侧；两名正面队员各完成一个节点，侧翼队员完成两个节点，14 条命令接受；18 次请求预算耗尽后正常停止。此前诊断试跑用了 24 次请求，本轮合计上限 42 次。
- 画面：`output/world-components-check/engine/output/world/` 下三张结构截图。

上述验证证明链路、任务进度和受约束组合有效，不代表所有组合已经完成平衡、长时间连续通关或宣传视觉质量验收。

## 生成上下文

`world/context.py` 为生成侧单独构造模型视图。DeepSeek 收到双方存活、血量与压制摘要、控制来源、本段任务进度、最多 12 次全场采样、最近 6 次组合、最近 4 次施工失败及上一轮节奏。未知压力保持未知；没有操作级证据不能推断玩家能力。建成记录不等于通关记录。

JEV 收到平滑后的方向与激素、战况及任务摘要、组合历史和失败约束；选项说明只出现在问题中，不再重复附在状态里。两者均不接收建筑零件、完整关卡 spec、碰撞盒或旧占旗目标。原始状态和精确位置仍留在引擎，候选过滤、过期检查与施工校验保持不变。模型上下文日志记录字符数，不将其当成 token 数。

本次对保留的真实快照做相同空采样窗口对比：已有一段构建历史，DeepSeek 状态从 5595 降至 1446 字符；见 `output/world-context-audit/`。这是离线输入对比，没有新调用真实模型或证明战术质量改善。12 项导演、6 项场景、30 项战术检查通过；已运行的 Python 进程需要新开会话才能加载修改。


## 逐兵执行与兵力选择（2026-09-21）

固定与无限模式共用逐兵并发执行器：每兵最多一个请求在途，共享指挥、执行校验、预约和总预算。按请求开始计的最小间隔为 1 秒，独立请求返回后不再额外等待 1 秒；线程池同时执行上限保持为 3。本地动作继续执行，不等待其他兵的模型结果。

生成 JEV 额外选择友军补充 0–2 名、守军 2–3 名。友军总数不超过 5，所有存活单位不超过 15；在开始施工及提交时检查容量。友军位于新区域入口位置槽，双方均有施工预览，完成后一起激活；新兵为 50 血。当前敌军选择为既有部署列表的前 2 或全部 3 个位置，并非新增的独立编制设计。

本轮逐兵并发与导演 Python 检查、Godot 构建合约检查已通过；尚未做同场景真实模型速度对比，不能据此声称模型对战变快或变聪明。


## 地面结构更新（2026-09-21）

三种结构现在分别是窄入口进入广场、侧向转角走廊、中央缺口分隔的双路。仍沿前沿方向拼接，但每段不再是完整矩形地面。catalog 的 floors 矩形并集同时用于施工预览、实际地面及物理碰撞；会话副本的寻路重建根据同一数据将无地面区域标为步兵和坦克禁行。原游戏源码不改动。

保留 48 个参数组合，重新布置适配结构的掩体、支援位和守军位置。构建校验覆盖入口、出口、侧路、支援位、守军及友军补充位的可达性。所有组合检查通过；三种结构各用真实单位 tick 走完侧路，验证全程位于地面且缺口不可通行，记录位于 output/world-shapes/traversal.log。无新真实模型对局验证；新会话加载生效。

地图不显示路线说明、清场说明或守军施工文字；必要状态保留在屏幕状态栏。暂未实现任意方向扩图、高低层地形或坦克编制生成。


## 滚动区域（2026-09-21）

正常保留最近两段已建区域与一段施工预览。新段激活后允许短暂三段并存；最老区域中没有活单位且没有活单位的当前路径返回该区域，才卸载地面节点、碰撞、旧掩体及尸体，并收缩 bounds、重建步兵/坦克寻路网格、刷新控制版本。仍有效的移动目的地重新寻路，不传送单位。

后方被占用时最多保留三段，暂停继续构建直到可卸载，防止无限累积；这也意味着长期落后的队员会阻止扩图，需要战斗指挥带队前进。开场静态场景保留作为背景，退出活动范围后不再可走。特效仍使用引擎原有池化管理，没有新增跨模块强制清理。

运行态仅保留最近六条构建记录与128个操作去重ID；完整历史使用原有Harness日志。区域序号递增不复用。九段引擎测试通过：卸载七段、保留两段，导航网格宽145格；确认占用阻止卸载且单位位置不被修改。证据 output/world-rolling/rolling.log；尚未做真实模型长时间远征验证。
