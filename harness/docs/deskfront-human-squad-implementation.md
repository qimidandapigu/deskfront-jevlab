# 1v1 拟人小队实现与验收

日期：2026-09-21。范围：Harness 和 `C:/game/deskfront-jevlab` 原生引擎；未提交 Git。普通 1v1 默认启用，旧版协同、无限生成保持各自入口。

## 使用

打开 <http://127.0.0.1:3777/runtime/deskfront>，选择「1v1 · 拟人小队」和「DeepSeek 规划 + JEV 小队」，启动真实游戏。双方各三名原生步兵，模型方可换边，对方为原生游戏 AI。开场双方暂停，等 DeepSeek 规划、JEV 首条命令获 Godot 接受后，倒计时三秒开战。

命令行：

```powershell
npm run play -- deskfront --variant duel --backend jev --options '{"modelFaction":"green","opponent":"game_ai","behavior":"human_squad"}' --max-requests 60 --duration-ms 180000
```

`--backend mock` 是明确标记的本地规则基线；它不证明真实模型效果。`behavior=legacy` 可保留普通 1v1 逐兵控制对照。

## 四层责任

| 层 | 当前实现 | 边界 |
| --- | --- | --- |
| DeepSeek | 从原生导航区域中选目标区域，说明目的、风险、重评和完成条件 | 不下逐兵坐标或射击命令 |
| JEV | 选择 advance / cover / bound / flank / hold / regroup，或延续当前行动 | 命令坐标由批准的 DeepSeek 区域产生 |
| Godot | 稳定成员与站位、虚拟队长、展开/纵列、原生寻路、真实火力交替、即时自保、弹丸碰撞 | 持续执行已接受意图，远端模型等待不冻结士兵 |
| Harness | 常规复核、事件合并、角色独立在途请求、预算、超时、旧回复丢弃和真实回执记录 | HTTP 202 只是入队，Godot ack 才计执行 |

JEV 常规复核为 5 游戏秒，DeepSeek 为 20 游戏秒；接敌、近距离危险、成员损失、掩体失效、通路受阻等可提前唤醒。引擎协作检查为 0.2 游戏秒，物理和单兵动作继续逐帧运行。网络超时采用墙钟，手动暂停不消耗游戏时间复核。

DeepSeek 计划还包含阶段、明确等待条件与 5–30 游戏秒的阶段复核期限。模型能看到同一区域累计时长、到达时刻、各兵实际射程、目视敌距离、射击证据和接近进展。健康成员持续 12 秒没有接近、射击或取得掩体，且可见敌全部在射程外，会唤醒重评；这只是重新判断的证据，不硬编码强迫冲锋。

## 文章对应与游戏能力

依据 Chris Jurney 的 [Company of Heroes Squad Formations Explained](https://forum.arongranberg.com/uploads/short-url/rWod3K2KhNWcOEdjewnsLXQKU6A.pdf) 中虚拟队长、未来锚点、稳定队形、速度调节与目的地预约站位思路，接入本项目现有导航和碰撞。没有复制《英雄连》源码，也没有把本文方案的调度参数当成原文结论。

- 行进时保持稳定成员关系、间距；窄道收拢，出窄道展开；虚拟队长不会抛下落后成员。
- 到达后各自选择真实可达的独立站位，利用有方向的掩体；地形破坏后重新检查。
- 掩护推进要求支援者有射界、弹药、低压制与近期火力。缺少支援时允许低压轻武器成员短步建立射位，受压立即停止；持续失败上报。
- 恢复受压卧倒和匍匐、掩体缩回与局部重整。拟人模式取消夺旗告急强制关闭自保的捷径。
- 枪弹、火箭和炮弹逐发散布，以武器基础散布、精度和压制影响角度，最终伤害仍走实际弹丸、姿态 hit box 与掩体碰撞。
- 模型只见小队实际目视目标与至多 6 秒的旧观测。观众全场快照不直接进入模型决策。

`flank` 是向 DeepSeek 批准的侧方区域机动，当前没有新增全局包抄搜索器。`regroup` 是局部集结，保留战略目标；`cover/hold` 也不表示已经到达目标。角色性格、复杂动画、任意多小队战略分工仍是扩展方向。

## 单兵情绪气泡预览

在同一次 JEV 执行请求中，除小队意图外，为每名存活的己方成员增加独立情绪选择：冷静、警觉、紧张、害怕、坚定、安心。没有增加逐兵独立网络请求；DeepSeek 不选择气泡。每个选择通过 `unit_emotion` 单兵指令提交，继承阵营、局次、控制权与时效验证；收到 Godot 回执才记录接受。无效或遗漏的情绪不会替换为伪造模型选择，也不会阻止有效小队行动。

引擎在士兵上方绘制带表情图案的中文气泡，颜色区分情绪，重叠时错开并用连线指向对应士兵。气泡有效期为 12 游戏秒，死亡或过期隐藏。该版本只表达 JEV 选择，不修改恐惧、生存阈值、导航、伤害或小队任务；“害怕”与自保行为的关联尚待下一阶段实现。原生 AI 对手没有伪装成 JEV 输出的情绪。

验证：控制器 29 项、Godot 小队机制 28 项、原有语义 113 项、接口 4 项和既有 LM 15 项通过。真实模型预览 `deskfront-6b5131f2-cbf3-4d89-802c-f433dc6103b9` 已看到中文气泡与真实模型选择，证据保存在 `output/emotion-preview-state.json` 与 `output/emotion-preview-history.json`。

后续顺序：先修正附近掩体选择和到位判定，再实现受火压力与缓慢恢复，最后把情绪表达与这些真实状态联动。气泡展示成功不等于求生行为改造完成。

## 预览反馈修复：空射与原地等待

气泡预览的实际记录发现红方 `last_shot_target=blue-3`，但蓝方在 1v1 中是 `parked` 的未参战单位。原因是原生 `find_target` 遍历全部单位，而可见性判断没有检查目标部署状态。现在目标查询、可见性和最终开火均排除未参战目标；这不是用散布解释错误射击。

同时调整小队保护：附近掩体允许在战略中心周围有限偏移，约束在候选评分之前应用；到达区域后可以继续走向附近掩体，不被拉回中心站位。接近目标与保护到位分开，保护查询失败持续两秒会报告 `no_reachable_protection` 并标记 `blocked`，不能继续当成正常成功。每兵保护状态进入 DeepSeek/JEV 上下文；规划明确本模式不自动回血，不能靠反复续期等待恢复生命。

验证：Godot 小队机制 31 项、既有语义 113 项、接口 4 项、LM 15 项、Harness 控制器 29 项通过。新增用例覆盖未参战对象不可感知/瞄准、最终射击拦截，以及空地保护失败必须上报。真实复验会话记录在 `output/cover-fix-session.txt`。这些修复不等于已经完成全部恐惧、自保与观赏性设计。

真实复验 `deskfront-552b304e-8f54-4a73-839c-20f9688e3c48` 的 27.6–51.9 游戏秒采样中，记录到的红绿射击目标均为对方参战单位，没有蓝方目标；三名绿兵都分别出现过 `in_cover=true`，且存在实际位置变化。小队阶段出现推进、建立掩护和重整。证据：`output/cover-fix-observations.json`。这是该时间窗口的实际反馈，不代表任意战局都不会停滞。

## 受火自保补充（2026-09-21）

此次在现有掩体搜索范围和保护状态修正上继续调整：

- 健康士兵有近期真实受击/近失弹证据时即进入自保，不等到残血或高压制。单纯看见敌人不会触发恐慌。
- 已有掩体优先缩回；无验证可用掩体时就地压低姿态，停止原推进，不再自动向空地退行。安全窗口过去允许恢复姿态。

- 现有掩体逻辑允许目标周边有限偏移，并区分 seeking/protected/unavailable；无可用保护会报告受阻。

## 任务持续性优化（2026-09-21）

- DeepSeek 的持续任务明确为进入并守住旗圈，交战服务于清除阻碍。新增 objective_flag 区域，落点来自原生可走采样且处于实际旗圈内，避免只到达附近区域中心。
- 传入旗主、真实占领秒数、静止和开火证据；阶段到期且全队静止、没有近期火力或急迫自保、也未实际守旗时，不再提供无限 hold/cover/continue_order。相同区域的被动等待续期保留最早期限。
- 引擎对旗圈内目标限制终点掩体偏移，避免已经到达却被普通周边掩体选择拉出任务范围。即时受火自保仍有优先权。
- 低血量本身不构成等待豁免；实时自保标记与装填、压制仍允许短暂等待。本轮没有添加自动回血。

验证：Harness 控制器32项、Godot小队机制37项、既有语义113项、小队接口4项、LM接口15项通过。

真实 DeepSeek + JEV 会话 deskfront-97b1283b-2f2b-4adf-a985-85f211e64e5d 正常结束，error=null。原生28.0秒采样已记录 green-2 在旗圈内且占领0.9秒，最终57.1游戏秒绿方守旗满30秒获胜。证据：output/mission-optimization-evidence.json；完整原生快照位于该会话 engine.jsonl。

边界：这是一次真实任务闭环验证，不是多局拟人观赏性验收。另两名士兵的协同站位仍有改善空间；未宣称所有停滞都已解决。实时验证后仅补充了区域用途上下文字段、规则基线合法选项兜底和受火恢复边界断言，并重新通过32项控制器检查。

## 文章机制落地：持续推进与有限掩体偏移（2026-09-21）

参考 Company of Heroes Squad Formations Explained 的行进中局部偏移与归队思想，不把其 Leapfrogging 等同于必须已有实际压制火力的战术交替推进。本轮改动在原生 scripts/human_squads.gd：

- advance/flank 不再仅因敌人进入射程就全队等待掩护；近期受火、压制或即时自保仍触发谨慎处理。JEV 明确选择 bound 时保留真实火力要求。
- 普通行进允许一次一人向前方近处真实掩体偏移，最多2.5游戏秒，随后归队，4秒冷却；无可用掩体继续行进。死亡或超时清理偏移状态。此实现是有限离队，不是原文80%插值的软偏移完整复刻。
- 支援条件超过5秒不满足时标记 blocked 并发事件，Harness 不能把它当作健康执行继续保留；危险消退后从实际小队位置恢复队形锚点。

不改变 DeepSeek 区域权限、JEV 意图权限、情绪或伤害参数。未在本轮完成专职占旗手与外围支援的角色分配，也不宣称实现完整论文。

原生机制40项通过（包括射程内接触不单独冻结推进、偏移到期归队、无支援超时明确受阻），Harness控制器32项通过。真实对局与最终回归记录见 output/formation-optimization-evidence.json。

上层进度补充：为每兵独立记录 approach_at，仅真正缩短到目标区域的距离才刷新；射击和切换掩体仍属于战斗活动，但不能刷新接近进度。接近/试探/重新定位阶段到期且所有成员20游戏秒未缩短距离、无人进入目标区域、也未守旗时，下次DeepSeek规划暂不提供当前区域（存在其他可达候选时），要求改选机动/撤离区域。引擎即时自保不被取消。控制器33项通过，包含开火不重置接近进度与候选约束验证。
