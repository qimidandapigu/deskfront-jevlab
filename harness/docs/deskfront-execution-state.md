# 执行状态与意图缓冲

命名与职责以 [意图执行器（IntentExecutor）约定](deskfront-intent-executor.md) 为准：仅指意图缓冲区 + 执行状态机。本文为实现历程，不代表所有目标已完成。

## 研究依据

- Epic StateTree：分层状态、进入条件、任务及转换；按转换触发重新选择状态。https://dev.epicgames.com/documentation/zh-cn/unreal-engine/overview-of-state-tree-in-unreal-engine
- Epic Behavior Tree：黑板存储事实，行为树执行逻辑，事件与中止机制驱动反应。https://dev.epicgames.com/documentation/unreal-engine/behavior-tree-in-unreal-engine---overview

这些资料不意味着队列自动消除竞争。项目采用的方向是：共享事实板、有限意图缓冲、明确执行权和生命周期，不移植 Unreal，也不增加模型。

## 目标架构

战略目标 -> 小队职责 -> 每兵意图槽 -> 唯一动作执行器 -> 引擎移动/姿态/射击。

事实板记录感知、实际射界、伤害、命令版本；不自行下动作。意图槽按来源与版本替换过时意图，不用无限 FIFO。执行器仲裁死亡/失能、即时避险、团队交接、个人任务及队形维护，记录开始、中断、恢复、失败与结束。运动执行权须唯一；允许兼容的瞄准/装填动画并行，不让两个任务同时写同一通道。

## 本轮已实现

- 修复等价团队命令换编号时，个人动作和已用等待资格没有同步迁移的问题；迁移不延长期限。
- 个人动作使用 active -> suspended -> revalidating -> active/失败 状态；每兵只保留一个当前意图，记录最近 8 次状态转换。
- 避险时保留意图，团队站位逻辑尊重挂起所有权；即时引擎避险仍优先。
- 危险解除后等待避险路线完成。换位必须重新走原有可行性检查，不复用旧坐标或旧路线；等待必须仍有保护。
- 超时按原期限失败，新任务版本不允许复活旧动作，失败发送具体原因。

## 验证与边界

个人执行探针 16、小队合同 62、语义 114、Harness 44、个人 Harness 10、接口 19 项通过。

目前是个人任务生命周期的第一阶段，不是完整状态树或全引擎单写者改造。队形、火力修正、自保及装备系统仍存在直接修改路线/姿态的路径；必须逐项迁移并测试，不能声称竞争已全面解决。没有新一轮真实模型实战、视觉或性能验收。

## 第二阶段：统一普通移动入口

human_squads.request_motion 统一接收队形、驻位、射位修正、交替推进和个人换位的目的地请求。有效且未完成的高优先级移动阻止其他低优先级来源覆盖；完成、期限届满或任务版本改变后重新仲裁。等价命令迁移所有权，不重置期限。掩护交接期间禁止队形和射位修正调走掩护者。unit 中的掩体边缘修正也接入该入口，保留掩体属性。

本次个人执行探针增加 6 项竞争检查，共 22 项通过；小队合同 62 项及战术安全 18 项通过。此入口不负责预测动作一定成功，导航仍执行原有检查。

范围限于 human_squad 的普通移动通道。紧急避险、显式取消路线、死亡、装备、姿态及射击不是全部迁入同一执行器；没有实现无限动作队列或完整可视化状态树。仍需固定场景与真实模型实战验收，不能将入口收拢等同于拟人达标或帧率改善。
