# 桌面卡库重复审计与精品化建议（2026-09-28）

后续状态：用户确认实施后，24 张作者库、几何导航、完整九桌用途任务书、卡片与方向原子选择已落地。当前职责见 [生成子系统](deskfront-generation-agents.md) 顶部；下文保留提出方案时的审计证据，“未实施”描述仅指当时。

## 当前结论和范围

建议下一轮把制作目标改为约 24 张有明显区别的精品卡，配套改进整张九桌地图的协调表达。24 是制作规模建议，不是论文结论，也不是已实施的生成限制。本轮仍保留 45 张普通卡；没有加禁重复配额，没有让引擎替换 JEV 的最终选择。

## 为什么换素材仍然相似

45 张卡有 44 种素材多重集，但 37 张恰好含四件物品。主要作者库使用四角插槽；当前区域路线把每格中心当作通行节点，迫使大物件避开中心。素材组合变化不等于画面轮廓或通路变化。

JEV 策划目前主要给整关主题和形态标签，逐格职责仍主要由代码生成。一次请求里的九道独立选择题也不等于联合提交九格设计。各格题面相似，可能各自偏好同一张卡；改稿时又同步偏好另一张。这是代码结构和两次回执共同支持的诊断，尚不是对模型内部计算机制的证明。

## 下一轮建议

1. 以八种桌面用途、每种三种空间组织作为作者制作计划。例如中央主物件环绕路线、错列物件弯道、沿边工作区等。旋转不算新卡，换小配件不算新构图。保全现有素材，不能只留下当前热门卡。
2. 让卡声明实际入口、出口、内部通路；导航绕物件走。先验证这种能力，再制作需要占据桌面中心的新布局，不能只删掉检查就声称路线可用。
3. 让 JEV 策划提出每桌用途、战术作用、视觉主角和邻桌关系；它们是模型意图而非引擎配额。搭建仍能从全部卡选择、旋转和修改。
4. 核实 JEV 后端是否支持一次结构化提交整图及一次结构化补丁。目前多道 `choice` 的批处理不能直接当成这项能力。若后端不支持，应明确接口边界，不能只靠新增“避免重复”提示词就宣称解决。
5. 质量和重复统计作为回执交给模型，不在提交后暗中换卡。目标保持策划、初稿、批改的调用次数，不恢复九格串行选卡。

上述 1—5 是设计提案，未在本轮落地。精品卡验收同时看质量和差异的方向可参考 [Procedural Content Generation through Quality Diversity](https://arxiv.org/abs/1907.04053)；该文不指定本项目卡数、主题数或姿态时间。

## 本轮已修复

`novel`（传记书）与 `warehouse`（档案纸盒）已有作者卡和渲染，却没有进入 `PROPS` 单物件编辑菜单。本轮补入，尺寸与作者卡的 `SHAPES` 一致，允许新增、替换并共享导出。菜单由 19 项变为 21 项。这修复“模型想改也选不到”的漏项，不代表模型实际已经选用了它们。

区域图 16 项测试通过，包括新增两种素材、90 度替换和共享 JSON 导出。没有用这个小修声称两关试玩的素材覆盖已经改善。

## 验收下一轮

- 在正常游戏镜头下比较主物件、剪影、遮挡高度与通行形状，不只比较卡名。
- 每张卡测试四个方向的部署、导航及射线表现。
- 对连续至少五关记录“素材是否存在 → 是否进入工具 → 是否被选择 → 实际是否可见”的完整过程。
- 同时报告高频卡占比、素材覆盖、布局差异与生成时延；五关只作为初步回归样本，不是多样性保证。
