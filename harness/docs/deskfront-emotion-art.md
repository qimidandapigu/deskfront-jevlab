# Deskfront 情绪表情

无尽推进的头顶表情使用 Twemoji 同一版本的原版图形。个人 JEV 的**动作请求与情绪请求已经分离**：动作只问局部行动，一次情绪请求让 JEV 分别回答场上每名存活士兵的表情。Harness 的 `SoldierEmotionScheduler` 为每名士兵维护独立观察状态，并将同队情绪问题合并为一次模型调用；引擎仍负责即时避险，死亡由生命值判定，不发出模型请求。F9 只控制表情显示，F8 仍单独控制战术图。

每次士兵情绪问题都向 JEV 提供全部 13 种表情，不根据血量、压制或事件删减选项。战况信息只供它参考；Harness 只校验返回值是否属于这 13 种协议允许的表情，不替它选择或改写结果。情绪只影响显示，不改变移动或开火权限。

情绪基线是**每名士兵距上次情绪请求满 20 游戏秒后再请求**；首次常规请求从小队有命令后开始。同一时刻到期的士兵合并为一次模型请求，刚因重大变化请求过的士兵不会被另一名士兵的常规批次提前重问。受伤、开始受压、本人收到来袭威胁预警、得知队友阵亡或引擎自保结束，都更新情绪数值和事实；是否提前请求取决于处境变化，不能仅凭事件名称决定。危险明显下降等无命名事件的变化也可提前刷新。普通提前刷新先等待 0.5 游戏秒以合并同一波变化，两次普通刷新至少间隔 6 游戏秒；受伤和队友阵亡引起的明显变化可走急迫通道，该通道间隔至少 2 游戏秒。

**强烈且稳定时复用上次 JEV 表情，最长 20 游戏秒。**调度器用上次请求时的 `arousal`、`pain`、`loss`、`relief` 和折算后的 `danger` 判断是否达到强度 0.55；再比较当下与上次请求时的危险、伤痛、队伍损失、可应对程度和缓解程度。最大变化小于 0.38 时，新事件只更新数值和事实，不另付一次模型请求；达到 0.38 时，即使仍在 20 秒内也可提前刷新。危险解除等处境变化同样适用。0.55／0.38 是待实战调优的游戏参数，不是心理学阈值。该规则只调度请求，不替 JEV 选择表情，也不阻止引擎即时避险。未触发新请求的事件保留给下一次有效情绪请求；另一名士兵的变化仍独立判断。整局提前刷新上限为 `min(8, max(2, max_requests // 8))` 批，通常保留两批给急迫变化。情绪与战术请求共用总额度，因此额度用完后不会继续调用模型。

`emotion_evidence` 来自原生受伤时间或生命值快照、压制阈值及持续时间、本人引擎来袭预警、引擎自保结束，以及真实队友死亡状态，最多保留最近八条事件。已送达的事件保留 20 游戏秒，未送达的事实留待下一次有效情绪请求，并附事件年龄。每个情绪问题标明士兵 ID 和该兵的匹配分，要求 JEV 只把该兵的受伤、来袭和压制当作本人经历；来袭预警不推断炮弹一定命中，队友死亡也不假定亲眼目睹。Harness 提交的只有 JEV 返回的合法 `unit_emotion`，不借情绪请求续期或覆盖动作。换小队战术命令不会让仍属于同一场战斗的情绪回答作废。

情绪问题现明确区分“此刻主观感受”和“仍能执行战术动作”：受伤但继续作战的人未必平静。JEV 先考虑近期本人事件、血量、当前威胁与受压持续时间，再参考上一表情；各选项附简短适用情境。受击不被硬编码成单一表情，痛苦、惊讶、警觉、紧张、害怕、愤怒或坚持都可能合理；没有证据时也不为了丰富画面而随机轮换。`emergency_ended` 只是引擎自保状态结束，不代表绝对安全。这是游戏表情提示，不是对真实士兵的心理诊断。依据是美国国防卫生署对战斗应激反应的资料：个人受伤和队友死亡都可能构成压力源，反应会因强度、持续时间和个体处境而异，也可能表现为高度警觉、恐惧、愤怒或迟钝（[概览](https://www.health.mil/Military-Health-Topics/Centers-of-Excellence/Psychological-Health-Center-of-Excellence/Psychological-Health-Readiness/Combat-and-Operational-Stress-Control/COSRs)、[生理机制](https://health.mil/Military-Health-Topics/Centers-of-Excellence/Psychological-Health-Center-of-Excellence/Real-Warriors-Campaign/Articles/The-Physiology-of-Combat-Stress-Reaction)）。具体提示在 `src/deskfront/soldier_emotions.py`。

模型服务返回 HTTP 429／502／503／504／529 时，日志记录具体状态；情绪调度器按每名士兵连续失败次数，在 2／4／8 游戏秒后重新采集**当前**战况，再向 JEV 请求，不重放旧问题。返回后如已超过 5 游戏秒，或期间本人新受伤、队友阵亡、关键情绪数值明显改变，则丢弃该兵的旧回答；同批其他士兵的有效回答照常提交。过期回答最早 1 游戏秒后重问。丢弃与失败不会由 Harness 自行填入表情，成功回执仍来自引擎。这个过期阈值是视觉表现参数，应结合真实服务延迟和回放继续调优。

### 数值化战况评估

个人 Harness 在情绪调度器里给每名存活士兵维护 `affect_appraisal`，并与事实事件一起放进该士兵的情绪 JEV 请求。它只做信息整理，**不输出表情、不改 JEV 选项、不影响战术动作**。这借鉴 [EMA 情绪评估模型](https://stacymarsella.org/publications/pdf/EMA_Dynamics.pdf) 的“事件意义、威胁和应对可能性随处境重新评估”思路；以下 0～1 系数和半衰期是 Deskfront 的可调游戏参数，不是论文给出的真实人类测量值。完整更新式在 `src/deskfront/affect_appraisal.py`。

| 数值 | 上升依据（本人可观察事实） | 回落或变化 |
| --- | --- | --- |
| `danger` 危险 | 受伤、压制、本人来袭预警、引擎自保、本人可攻击目标；无接敌仍留少量未知风险 | 危险消失后按 4 游戏秒半衰期回落，最低 0.12 |
| `pain` 伤痛 | 新受伤按本次失血占最大血量的比例增加，连续受伤会累加 | 10 游戏秒半衰；不把“自己命中敌人”当作受伤 |
| `arousal` 激活 | 危险、伤痛、突发刺激的合成驱动 | 驱动消失后按 12 游戏秒半衰期回落 |
| `coping` 可应对程度 | 可用掩体、可开火目标、有效路线提高；压制、自保或路径失败降低 | 随当前条件即时更新；这是可用办法估计，不是士兵的真实自评 |
| `strain` 累积消耗 | 激活水平较高时缓慢累积 | 150 游戏秒半衰；短暂交火不会直接变成“疲惫” |
| `loss` 队伍损失 | 收到队友死亡的队伍状态 | 40 游戏秒半衰；不推断本人目击 |
| `surprise` 突发冲击 | 刚受伤、压制首次升高或来袭预警 | 2.5 游戏秒半衰 |
| `relief` 缓解 | 危险确实下降，或自保结束且眼前危险较低 | 6 游戏秒半衰；自保结束本身不足以证明安全 |

`danger_change` 表示本次请求相比该兵上次请求的危险变化。数值只来自该兵快照和报告给他的队伍损失，不读取未发现敌人的位置。JEV 综合数值、事件和旧表情选主导感受：例如危险高而应对少可能更接近害怕，危险高但有掩护和火力也可能是警觉或坚持；这仍是开放选择，不按阈值固定映射。

为了避免 JEV 忽略八个原始数值，程序还据此计算 13 项 `emotion_support` 匹配度（均在 0～1，不归一化为概率）。例如 `calm` 同时考虑低危险、低激活和低伤痛；`alert` 偏向有办法应对的中等威胁；`nervous`/`afraid` 会随危险和无力应对上升；`hurt` 看伤痛；`relieved` 看危险下降；`sad` 看已报告的队伍损失。这些分数是**交给 JEV 的建议证据**，不筛选表情，也不在模型回答后替换它的决定。引擎依旧只接收 JEV 给出的合法表情。

游戏场景副本中，模型情绪 22 秒后失效，覆盖 20 秒常规间隔和少量请求延迟。没有有效 JEV 情绪时不显示表情，避免把“没有决定”误画成“JEV 选择平静”。阵亡始终显示引擎判定的阵亡图。该时长由 Harness 的场景装配补丁设置，原始游戏源码仍是 12 秒。

| JEV 可选表情 | 素材码 | 对应情境（提示，非硬规则） |
| --- | --- | --- |
| 平静 `calm` | 1f610 | 无明显威胁，稳定观察 |
| 警觉 `alert` | 1f928 | 发现动静但尚未受压 |
| 紧张 `nervous` | 1f630 | 暴露或支援不足 |
| 害怕 `afraid` | 1f628 | 受火、受伤或同伴损失带来恐惧 |
| 坚持 `determined` | 1f623 | 受压仍执行任务，不表示可以忽视危险 |
| 生气 `angry` | 1f620 | 受挫或同伴受伤带来愤怒，不改变执行权限 |
| 安心 `relieved` | 1f60c | 刚脱离危险或进入保护 |
| 难过 `sad` | 1f622 | 得知队友损失或严重失败，不假定亲眼目睹 |
| 惊讶 `surprised` | 1f62e | 突发接敌，短时情绪 |
| 困惑 `confused` | 1f914 | 路线受阻、目标消失、命令矛盾 |
| 疲惫 `exhausted` | 1f629 | 持续受压、长时间交战或资源低 |
| 痛苦 `hurt` | 1f915 | 自身受伤 |
| 开心 `happy` | 1f603 | 脱险、配合成功或明确战果 |
| 阵亡 `dead` | 1f635 | 引擎判定生命值归零 |
