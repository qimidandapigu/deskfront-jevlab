# Deskfront 战斗决策分工

同一套 Agent Harness 调度指挥 Agent、小队 Agent 和逐兵 Agent；红绿两队状态、命令与预算各自独立。IntentExecutor 只负责意图缓冲和执行状态，定义见 [意图执行器约定](deskfront-intent-executor.md)。关卡生成由另一个子系统负责，不在此战斗契约内。

| 层级 | 输入与输出 | 调用上限 |
| --- | --- | --- |
| 指挥 DeepSeek | 读取任务、可信敌情、真实执行效果；输出候选 `region_id`、阶段、目的、风险和可选等待条件。区域 ID 必须由 Harness 的原生导航目录提供；不选择逐兵动作。 | 常规每 20 游戏秒检查；关键事件可提前，但两次请求至少相隔 5 墙钟秒。 |
| 小队 JEV | 读取指挥目标和每兵状态；输出小队意图、逐兵职责，以及逐兵目标区域和区域通路编号。每名士兵有自己的 `region_id`、`region_path` 和路线中心点。 | 常规每 5 游戏秒复核，有进展时跳过；事件可提前，但两次请求至少相隔 2 墙钟秒。 |
| 士兵行动 JEV | 读取本人状态、团队指令、队友报告、个人实际开火与命中时间，以及调用时引擎给出的候选位置；输出短时动作、候选位置编号、适用时目标编号。 | 每兵至少相隔 1 墙钟秒，答复后有 5 游戏秒复查间隔；短暂自保状态或射线受阻原因变化不清除这个间隔，新命令、职责或目标区域则可立即复查。有效职责不要求定期付费确认；每队最多 4 个并行个人模型请求。 |
| 士兵情绪 JEV | 独立读取逐兵事件、状态和情绪数值；一次请求可分别回答多名士兵的头顶表情，不下行动命令。 | 每兵距上次请求满 20 游戏秒常规复查，同期到期者合批；强烈且稳定时复用上次结果，处境明显变化可提前刷新。详见 [情绪表情](deskfront-emotion-art.md)。 |
| IntentExecutor 与引擎 | 校验任务版本、动作权限、候选位置及真实路径；仲裁移动、姿态和安全中断；引擎计算射线、射击、碰撞和伤害，返回真实回执。 | 每游戏帧运行；不调用模型。 |

士兵可选动作包括继续当前任务、移动到候选点、快速冲向候选点、卧姿短进、占据候选掩体、掩体探头射击、对可见合法目标集火、报告职责受阻。候选点来自当前区域和小队分配的区域通路，最多 12 个，经原生导航和占位检查。掩体、射界、路径长度和可能遭攻击人数作为选择信息；暴露和掩体质量一般是软条件，立即危险仍由引擎优先处理。JEV 不能创造坐标，回复中只携带候选编号；执行瞬间还会重新校验。

所有模型选择都先进入 Harness 命令队列，HTTP 202 只表示入队。引擎接收、路线完成、射击和命中分别记录；失败回执唤醒小队。士兵局部尝试 5 游戏秒仍无移动、火力或掩护收益时，升级给指挥复核，每个成员和命令只升级一次。连续 12 秒的其他测量停滞保留既有兜底检查。个人表情由独立的情绪 JEV 回复决定，阵亡表情仍由引擎固定处理。

## 当前边界与验证

### 个人动作与落点关联（2026-09-30）

个人 JEV 现在只回答一道 `action` 选择题。每个选项绑定动作、候选位置和适用的目标，例如 `move_to_site:C3`、`peek_fire:C3:red-101`；探头选项只能绑定该掩体原生验证过的敌人。Harness 保存选项映射并按映射下达命令，不再把独立的动作、位置、目标回答拼接起来。引擎仍在提交时复验，HTTP 入队仍不算执行成功。

上下文中的 `assignment.goal` 优先使用该士兵的小队分配落点，而不是全队共享落点。工具补充最多 8 条、每游戏秒一次的真实位置采样，以及这段实际路程、净位移、所在任务区域和局部执行状态。每个候选标记与个人任务落点的直线距离增益、是否最近真实走过和距本人距离；直线增益不是路径成本，局部到位不等于职责完成。它们是模型参考事实，不作为禁止回撤、自动选推进点或修改分工的规则。

`continue_task` 不提交新的个人移动指令。明确的新选择仍可替换落点；同一命令的新旧目标仲裁继续由 IntentExecutor 管理。保持既有调度间隔、预算与并发，不增加模型调用、寻路或逐帧全图扫描。已有游戏副本需要新开一局才加载这些变化。

同日核对实际副本发现，避让安装钩子之前仅匹配 `var steered=target`，会残留原表达式的横向推开部分，拼接到失败回退中。现按完整原表达式替换，普通避让失败回到原目标；现有避让限幅不再被这条回退绕过。钩子测试检查原生源文件的最终替换结果，Godot `FORMATION_STABILITY` 检查通过。
