# 重复开销检查

已删除可确认的重复工作：
- HumanSquadController.snapshot 内同一上下文和个人状态从各构建两次改成各一次。
- host 常规双边状态发布复用主阵营快照，不再额外构建一次。
- 观察台完成会话后停止网络轮询和重复绘制；后台标签页暂停请求。新会话 ID 仍可开始轮询。
- 折叠的原始快照不再每次 JSON 格式化；展开时读取最新数据。

未删除有效功能：紧急预警、实际射击安全、命令版本校验及回执跟踪。没有足够证据将某个模型层或工具整体判为无用。

发现但尚未优化：引擎每 0.2 秒生成的单位快照仍包含双方可交战性查询；标准返回为兼容性同时包含 squad/coordination 等重复视图。需测量并检查消费者后再瘦身。host 有结束时关闭引擎、模型控制器、HTTP 服务的清理路径；仅凭代码不能保证所有异常场景都无残留。

验证：Harness 44、个人 10、页面 5 项通过；host Python 编译通过。原生 live runtime 测试未启用而跳过。本轮未重启正在提供旧页面的服务，也未测量新旧 FPS。既有低帧率问题仍未完成验收。

## 引擎快照查询去重

game.snapshot 为每次快照创建独立字典，按有方向的 shooter:target 复用可交战性查询。A 对 B 的射界与 B 对 A 分开存储；下一次快照不沿用，实际射击和碰撞检查不使用该缓存。双边都进入快照、双方在射程内时，每个方向由两次查询变为一次。新增 snapshot_units 耗时统计，尚无整局 FPS 改善证据。

5 项专门探针验证复用、方向区分、下次重新查询以及直接校验不受缓存影响；语义 114、接口 19 项通过。当前旧会话不热加载新引擎代码。
