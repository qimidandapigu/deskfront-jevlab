# 桌面物件与区域通路

精品卡可以把电脑、书堆或文件架摆在桌面中心。`region_graph.py` 与 `region_graph.gd` 在最终卡片、旋转和单物件修改确定后，依据实际碰撞几何计算可站立点及通路，不再要求小兵经过每张桌子的几何中心。

两端使用相同的 0.025 米网格。物件周围保留 0.0401 米余量，其中 0.0001 米用于避开浮点边界分歧；地面外缘仍须支撑士兵身体。每张桌子先找能连接所选各边的真实连通空间，再在其中较大的空间里取靠近中心的安全站位。每条选中的桌间连接都须能在这两张桌子的范围内连接站位。主路和侧路由真实网格路径串接，仅压缩连续共线点。守军与增援位置也必须落在可达空地上。

这是对导航、路线展示与部署位置的解释，不是改图：组件位置、种类、旋转、连接和模型提交均保持原样。若精品卡最终设计确实封死一条指定连接，返回 `blocked_region_connection`，不偷偷打开另一条边、替换卡片或挪开道具。

旧卡库仍能重放。不需要几何导航的旧配方继续保留原路线数据；旧卡与精品卡混用时，旧卡保留原生导航允许从相邻桌绕行的语义，路线根据最终实体碰撞重新计算，不承诺旧路线坐标逐字节不变。真实关闭的墙仍然阻挡全图路径，这条兼容路径也不会改组件或重新打开连接。

救援任务先落实文具堡垒的墙体，再以堡垒中的救援点为终点重算通路。不能沿用加墙前指向桌沿的路径点。外围守军除位置空闲以外，还必须从入口真实可达，避免把守卫部署到物件围出的孤立角落。

计算只在关卡编译和原生搭建时执行，不进入每帧循环。Python 缓存相同碰撞几何的网格。`design_card.navigation=geometry_grid_v1` 标识新的通路计算，`region_anchors` 记录站位，`friendly_slots` 供生成器和原生引擎使用同一组增援点。

验收入口：`test/deskfront_world_geometry_navigation_checks.py` 检查中央物件、四向旋转、完整路线段、部署和真正封路；`src/deskfront/world/geometry_navigation_contract.gd` 对照 Python 生成的 fixture 验证 Godot 输出、原生 AStar 可达性及每段路线的碰撞网格。
