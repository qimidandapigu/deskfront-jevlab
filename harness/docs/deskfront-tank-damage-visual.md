# Deskfront 坦克受损视觉约定

目标是在常规战术镜头下，让玩家看出坦克哪里被炸、是否还能移动、是否已经成为残骸。生命值与碰撞仍由 Godot 单位负责，视觉节点只读取真实受伤结果。

## 画面语言

- 保留大部分阵营涂装。焦黑是贴在受击侧车体、炮塔及履带上的局部烧痕，不把完整炮塔或整辆车换成黑色。
- 每块烧痕有深色核心、烧褐边缘和不规则轮廓。三个相邻部件使用同一受击侧，让痕迹看起来来自一次爆炸。
- 履带在重伤时向外、向下错位，配合实际引擎受损的减速结果。受击侧由命中来源决定；没有来源的测试调用使用固定右侧。
- 击毁后车身稍微下沉并倾斜，炮塔偏转，履带进一步脱位，但保持有高度的残骸。持续黑烟会遮住造型，暂不使用。
- 炸药包贴住首次撞击的装甲点，并跟随坦克移动和转向；引爆位置与视觉破损方向一致。

## 参考和取舍

- 《World of Tanks》的[战斗特效说明](https://worldoftanks.com/en/news/general-news/2-4-upgraded-vfx-sfx/)强调让穿透、弹开、装甲变形、烟火等反馈帮助玩家辨认发生了什么。这里优先保留命中部位和受损状态的可读性。
- Steel Hunters 美术总监在[载具破坏制作分享](https://80.lv/articles/setting-up-destructuible-cars-for-steel-hunters-pvpve-shooter)中将掉漆、烟灰和部件形变一起用于损伤阶段。当前低多边形坦克模型没有独立可断裂装甲板，因此先用局部材质与履带位移表达同一层次；真正的装甲破口需要专用网格资产。

## 验证

`test/deskfront_tank_visual.gd` 覆盖红、蓝两侧受损及凸起残骸的状态，并可用 OpenGL 截取正常游戏镜头。`test/deskfront_satchel.gd` 覆盖炸药包贴附、移动转向后的锚点、爆炸伤害、受击侧与履带破损的一致性。截图审查仍需和状态测试分别进行。
