# 战术小兵拟人化改造方案

日期：2026-09-21。状态：初始设计记录；首轮 1v1 实现已落地，实际范围和验收见 [实现说明](deskfront-human-squad-implementation.md)。本文尚未实施的扩展项不等于当前功能。用户已允许修改游戏引擎；此前 Harness-only 边界不再适用于这次改造。

## 目标与推荐架构

目标是可理解、连贯、有个体差异的小队战斗。保留夺点、推进、撤退等角色动机，验收重点改为可信反应与观看体验。降低 JEV 调用频率只是稳定决策的一环。

已确定架构：DeepSeek 负责规划和选择目标区域；JEV 选择并维护小队意图；引擎将其持续执行为每个士兵的移动、站位、探头、射击与自保。Harness 负责事件调度、预算、旧回复校验与记录。JEV 不得覆盖 DeepSeek 的长期目标区域，各层不能同时争抢单兵移动控制权。

单兵仍有自主表现：反应速度、谨慎程度、跟队倾向、近期受压记忆影响局部行为。这些是持续状态和受约束的偏好，不需要每个兵不断独立调用模型。特别任务可以由 JEV 显式指定某兵执行；执行器负责安排其他成员与其配合。

## 一、引擎提供持续的小队动作

先提供 6 类意图：结伴移动、依托掩体交战、掩护推进、向批准区域机动、固守观察、局部重整。当前 JEV 选择意图并决定是否延续，目标区域和目的由 DeepSeek 提供；不编造逐帧坐标。协作组、风险偏好及结构化结束条件是后续扩展方向。

引擎收到意图后维护整个生命周期：准备、执行、完成、受阻、被紧急反应暂时打断。每兵同时只有一个移动控制者。紧急自保可暂停当前意图，危机过去重新校验后继续；动画忙碌只延迟可兼容的操作，不能默默把旧命令覆盖回去。

### 行进与到达

- 共享前进锚点受真实队员进度约束；某兵靠掩体避让时，整队路线不跟着突然偏转。
- 开阔处展开，窄道收拢，出口恢复间距。落点必须检查路径，不把“偏移坐标可走”当作实际可达。
- 接近同伴不等于共享落点。到达后各自预约位置，避免交叉跑位和堵住友军枪口。
- 稳定左右位置和协作关系；个体偏移缓慢变化，并受通路、间距、火力方向约束。所有随机数使用可记录种子。
- 允许短暂停靠有效掩体再接上队伍；撤退采用偏向掩体的连续行进，避免在每个掩体前停下。

### 交战与自保

- 引擎负责近失弹压制、受火卧倒、掩体缩回、换弹及脱险恢复；不依赖远端模型响应。
- “支援准备好”以实际射界、武器状态和近期火力为据，不能因为计划写了掩护就让另一组冲出。
- 掩护中断时机动组可以暂停、找临时保护并报告；持续失败才请求改计划。
- 设置状态保持和不同的进入/恢复阈值，减少站起趴下与左右换掩体的反复切换。
- 无伤害并不代表行为无效：观察、掩体装填、等队友都可能合理；持续等待必须有明确条件和期限。

## 二、5 秒复核 + 语义事件

以下数值是首轮调参起点，不是论文结论，也不是最终性能承诺。

| 层级 | 调度 | 内容 |
| --- | --- | --- |
| 物理/动画 | 原引擎固定步长 | 弹丸、碰撞、根运动、姿态过渡 |
| 感知/局部执行 | 约 0.1–0.25 游戏秒；碰撞伤害可直接产生事件 | 更新威胁、掩体失效、队形、姿态；不调用模型 |
| JEV 小队选择 | 通常每 5 游戏秒检查是否需要复核；重大事件提前唤醒 | 延续、切换意图、选择队伍配合与方向 |
| 可选任务指挥 | 阶段完成/失败或约 15–30 游戏秒 | 调整整场任务方向，不选择微小落点 |

5 秒是默认复核节奏，行动仍有效且没有新信息时可以跳过模型请求。暂停冻结游戏时间调度，服务商限流和请求超时使用现实时间。游戏加速时也不能按倍速无限增加远端请求。

事件分为三类：

- 紧急：突然受到新方向火力、当前掩体被毁、近距离新威胁、当前路线变成暴露通道。引擎先做局部保护，事件同时触发重评；不等待凑满 5 秒。
- 协作：队友倒下、协作组失去火力、机动组到位、通路持续失败。仅唤醒受影响的小队/任务，不全场广播调用。
- 普通：距离和压制小幅变化、同一持续威胁、正在完成的正常换弹。积累状态，在常规复核时提供。

为每种威胁维护标识、严重度和版本，只在出现、跨阈值、方向显著变化、解除时触发。普通事件可合并约 0.2–0.4 秒，同类请求可设约 1–2 秒冷却；危险升级可以突破普通冷却。每个小队至多一个在途请求，期间新事件累积为最新待处理状态，不排出长队列。

回包同时检查 run_id、控制权、小队任务版本和相关感知/掩体版本。关键事实变了，旧选择不再下发；不因时间戳更新而无差别丢弃仍适用的答案。模型延迟或不可用期间，引擎继续已接受动作与自保，日志明确本地执行来源，不能声称产生了新模型决策。

## 三、感知、个性和近期记忆

观众可以看全局，但决策只读取该小队可知的信息：当前目视目标、近期枪声的大致方向、队友报告、敌人最后出现的位置和时间。丢失视线后不继续获取实时精确坐标，信息过期后不确定性增加。

过滤必须覆盖整个链路：不仅删掉模型输入中的敌人坐标，也要限制最近敌人查询、威胁点、选位评分、射界候选和引擎自动索敌使用的信息，避免从候选答案泄漏隐藏敌人。底层碰撞仍然读取真实世界，观众调试视图与角色知识分离。

个性先用三个可观察偏好即可：谨慎程度、跟队倾向、恢复信心的速度。结合最近受伤、近失弹、队友阵亡和成功到达掩体的经历影响局部偏好。状态有时间连续性，不每次调用重新抽性格；人格不覆盖物理约束或使士兵无故违令。

## 四、弹道与卧倒的收益

将上轮散布原型迁入原引擎，所有远程武器由方向散布和实际连续碰撞决定直击。移除无用的先抽“必中”步骤；分别配置步枪、冲锋枪、火箭和炮弹的散布与飞行规则，不长期共用一条从 accuracy 推导的曲线。

区分三个结果：直接命中、附近飞过导致压制、爆炸造成范围伤害。站/蹲/卧使用对应的身体几何，掩体遮挡进入真实碰撞判定。爆炸按距离与遮挡结算，不能宣称卧倒对所有射角、爆炸高度都更安全。散射弹必须有合理的射程终点、地面/桌面碰撞和重武器爆炸位置，不能在目标原来的中心平面凭空消失或爆炸。

当前固定正面采样得到的约 22% 命中下降，仅证明一个条件下卧倒的几何收益。正式验收增加距离、正侧后方、射手高度、低/高掩体、移动目标和不同武器矩阵，并检查实际弹丸伤害与动画碰撞体匹配。机理上的收益与整局观感分别记录。

## 五、第一段可玩切片

固定一张桌面：一本书形成遮挡、一条窄道、一组方向性掩体、一条可改变的侧路。两队每队 3–4 人；进攻队内部允许支援和机动分工。固定出生/目标/种子用于对照，交战过程不写死。

希望出现的可读过程：结伴行进→遭遇火力后分散找保护→一组建立实际火力、另一组短途推进→掩体失效或队友受挫→调整站位、撤退或重新集结。设置可控测试事件来覆盖分支，但不能把脚本演示算作 JEV 自主协作成功。

观赏性先靠场景中能看清的动线、合理持续的交火与休整、短促状态提示和合适镜头。可增加“等队友”“侧面来敌”等由真实事件生成的短提示。避免用长篇旁白替代实际动作，也不要每几秒强行制造事件。

## 六、实施顺序与验收

| 阶段 | 交付 | 通过后再往下推进 |
| --- | --- | --- |
| 1. 统一控制与基础反应 | 引擎内统一姿态/散布；拟人模式取消倒计时覆盖自保；明确动作所有权 | 原生规则场景下受火反应、掩体和碰撞正确，普通入口与 Harness 一致 |
| 2. 小队执行能力 | squad_id、持续意图、稳定编组、柔性队形、独立站位预约 | 窄道进出、队友倒下、掩体破坏不会导致全队乱跑或永久等待 |
| 3. 感知与 JEV 事件调度 | 可知信息视图，5 秒常规复核，事件去重，旧回复处理 | 固定输入和慢响应模拟验证触发、不重复下发与不中断有效动作 |
| 4. 真实模型切片 | 同一场景的原生规则基线与 JEV 对照、完整回放和日志 | 实际模型有有效决定和引擎回执；盲看录像评估自然度、连贯性、可读性 |
| 5. 个性与场景扩展 | 少量持续偏好、多地图与更多事件 | 变化可归因于经历/偏好，不损坏已有行动能力 |

验收分三组：硬约束（碰撞、有效站位、命令归属、回包失效）；行为指标（无故改目标、姿态反复、队友走散、有效掩体使用、事件到本地反应耗时）；人工观看（像不像人在反应、能否看懂协作、是否愿意继续看）。不把趴下次数、抱团时长或交火时长设成单独最大化的分数。

对照先保持同地图同种子，分别开关小队执行、事件调度和感知记忆，避免同时改变后无法判断收益来源。机制修改需运行原引擎 semantic_probe 和 Python 接口检查；真实模型调用/执行回执/实战观感分别报告。已知 Windows SQLite 临时文件占用等环境失败单独记录，不冒充全部通过。
