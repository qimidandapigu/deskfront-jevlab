# 小队任务一致性

本更新只属于 EXE 配套 SDK；不回写或验收保留的源码版。

JEV 的执行接口只接受 Choice / Score / Noul，不支持指挥模型的 JSON 计划。小队逐兵职责和路线改为同一个 Choice：`职责:本轮路线坐标/via`，保持任务单独为 `keep_assignment`。每兵最多三种职责乘本兵路线数；没有枚举全队成员组合，也没有另一次串行模型请求。跨成员题仍相互独立，不能因此宣称全队联合最优或一定形成包抄。旧的独立包抄成员题不再覆盖已经选定的职责。

坐标投影先于组合题生成。请求内私有绑定先把组合题拆回既有职责/路线字段，再由坐标绑定严格还原原生候选；同坐标不同 via 不合并，不吸附模型编造的坐标。生产消费非法的组合直接失败，不暗中替换职责或落点。`continue_order` 忽略本轮未使用的逐兵与装备分支。

驻守、保护与重整是有区域和目的的任务。`hold` / `cover` / `regroup` 共用目的、关注对象与复评合同；其他动作忽略这些条件参数。小队明确选择守备、等接触、维护射位、屏护任务或局部恢复，并选择关注的任务区域/已知对象与复评条件。合同中的 `member_areas` 来自实际选中的逐兵路线，`commander_reference_area` 只是指挥参考；二者不能互相冒充。个人 JEV 接收任务目的、所选区域和原生执行事实，仍从原生合法候选中选择精确位置，不能自行换战略区域。

`hold_relevance` 提供当前距离、射程、实际射击、路线推进与原生任务进度，供模型比较。没有近期射击、无目视敌人、正在装填或单纯离指挥坐标远，都不作为移动/守备许可；合理绕障、守备通路和等待敌人进入仍可选择。是否有实际价值由模型依据本轮事实复评；本次不声称改变了模型的全部战术偏好。

明确继续驻守会通过现有 `squad_order` 传输同一 order ID、完整未变分工及唯一 `task_review`。只有实际模型答复产生新复评 ID；轮询和同一答复重放不产生新授权。原生只在已有保持阶段达到复评状态后消费一次，不重置正在执行的路线/期限，不复活失败任务。个人有限等待与小队任务复评是两个生命周期；复评到期不是强制冲锋。

检查入口：`test/squad_task_coherence_checks.py`。夹具运行真实 `_launch`、坐标投影、任务绑定、收获与命令提交，只替换模型运输和原生回执；不调用付费模型，不代表完整 AI 对战结果。完整 wire 请求导出供真正 TypeScript JEV schema 适配器验证。
