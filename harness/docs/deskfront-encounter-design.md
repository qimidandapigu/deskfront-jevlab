# 从实时铺地到遭遇关卡生成

## 参考依据

1. Joris Dormans, Adventures in Level Design (2010)：把任务结构与空间结构分开生成，再映射到一起。论文也讨论了先单独学习动作、再组合动作和最终考验的任务组织方式。
   https://pcgworkshop.com/archive/dormans2010adventures.pdf
2. Mike Booth / Valve, The AI Systems of Left 4 Dead (2009)：根据队伍强度状态调节敌人分布与紧张节奏，形成升温、高潮、舒缓等阶段。
   https://steamcdn-a.akamaihd.net/apps/valve/2009/ai_systems_of_l4d_mike_booth.pdf

这两份资料提供设计思路，不证明本项目已实现相同效果。尤其本项目要求画面内构建，不能直接照搬 L4D 的出生策略。

## 推荐生成过程

战况和玩家证据 → DeepSeek 体验目标与节奏 → JEV 任务与空间候选 → Harness 检查和选择 → Godot 预览、构建、执行 → 根据真实结果评估下一段。

地图需要同时表达五件事：从哪里进入、为什么前进、哪里有威胁、可以选择哪些应对方式、何时算完成。

例子「清除前哨」：入口给安全观察点；正面路线短但暴露；侧路长但有断视线掩体；守军火力覆盖正面却存在侧面弱点；出口是任务完成位置。玩家能够从画面读出选择，士兵也有可执行的支援和推进任务。

DeepSeek 决定此刻应舒缓还是挑战、应提供哪种能力发挥机会，保留不确定性。JEV 决定任务类型、路径关系、掩体布局、敌我部署和增援入口。Harness 只做合法性、预算、去重与执行验证，不假装自己是生成模型。

## 地图质量应如何检查（目标设计，尚未全部实现）

- 硬性条件：入口到任务目标可达；侧路确实形成不同路径；出生位置不重叠；没有地形压住现有单位；施工期间有预告；旧区域状态保持。
- 战术条件：至少一种掩体能遮挡实际威胁；正面和侧面路线有明确代价差；敌人的有效射程与部署匹配；小队能形成支援站位。
- 节奏条件：新区规模与现有部队和交战密度相称；当前任务未完成不无限扩张；休整阶段减少威胁，不把每次成功都变成加难。
- 多样性条件：比较最近几段的任务、路径拓扑、掩体轮廓与兵种组合，而非仅改变颜色。重复教学可以保留技能主题，但应变化空间。
- 体验条件：观众能说出当前目标和至少一种打法；实机中有推进、交战、完成反馈，而不是只看生成计数。

建议后续每次生成数个候选，以确定性寻路、遮挡检测、短时模拟淘汰不合格候选，再由 JEV 选择符合体验目标的方案。不能只给模型一句“精心设计地图”，就假设它完成了质量验证。

## 本轮已实现的范围

- 四类推进/遭遇模板采用不同布局：交错纵向掩体、中央遮挡与侧路、前哨纵深阵地、增援集结空间。施工预览使用同一布局数据。
- 删除旗帜、占旗倒计时与占旗提示。任务使用绿色出口标记与名称。
- 多数存活绿方步兵抵达出口才开放下一段；前哨还要求清除出口附近红军。没有存活绿兵则任务失败，不虚报完成。
- 自动控制的小队获得任务推进/接敌支援行为，不再依赖原占旗 AI；手动控制仍尊重玩家输入。此次不是完整的双兵协同或救援 AI。
- JEV 上下文加入单位、边界、近期掩体、障碍与当前任务。禁止连续同模板；两段都没部署新部队后仅提供敌方前哨/友军增援选项。实际出生仍受人数与可达位置约束。
- 摄像机聚焦当前前线，避免持续缩小整张地图。

当前仍是四类模板选择，不是自由生成任务图；救援、护送、侧路价值评分、短时模拟评估、长期玩家画像和旧区域回收尚未完成。仅靠本轮改动不能宣称达到宣传级关卡质量。

## 验证边界

Godot 合约验证任务未完成不展开、真实路径生成、抵达后开放下一段、旗帜隐藏及旧状态保持；原战斗语义探针用于检查普通模式回归。共享协议实机测试要求两块区域实际建成并获得回执，不能用模型成功响应替代。完整节奏循环和战术质量仍需要更长实机观察。

本轮结果：27 项 Godot 合约、113 项原战斗语义、8 项 Python 导演检查、类型检查通过。真实双模型连续两段测试通过，报告为 `output/world-jev-1789896357580/report.json`；离线实机报告为 `output/world-mock-1789896241042/report.json`。尚未完成新版原生画面的人工视觉验收。
