2026-09-21

旧实现把 DeepSeek 接到 logprobs 单选题后端，每题只输出选项字母。它只能选预设打法和路线排列，不能生成计划。这是接口限制，不是已经证明模型缺少指挥能力。

本轮增加 `json` 问题类型。仅 DeepSeek 后端支持生成 JSON 对象，使用现有 Harness 模型配置、请求预算、超时、日志和真实 usage；JEV 与 mock 显式拒绝此类型。普通选择题仍走原有打分接口。生成上限2200 token，截断和非法结果不安装，不将自由文本伪装成概率评分。

DeepSeek 自行生成总体意图、每兵职责、协作对象、可选路线、目标、完成条件和重评条件。完成条件支持观测可验证的占旗时长、目标阵亡、回血比例和到位位置；这些是状态检查词汇，并非预设战术剧本。字符串重评条件供模型理解，Harness不冒充已自动解析全部自然语言；它另对阵亡、完成和持续无收益发起重评。

JEV仍每轮共享一次整队请求，各兵独立返回动作；每兵读取完整计划与其他成员实际状态。它不是整队联合动作搜索。暂不拆成单兵请求，尚无相同条件的对照证明拆分更好。正常执行周期为请求完成后至少1秒；指挥默认完成后10秒重评，事件重评最短间隔8秒。

阵亡只清理死者任务、占位和关联协作对象；存活成员保留任务与反馈。JEV不再以“已有指挥计划”为请求前提；初始等待或指挥失败期间仍基于真实观测自主选择。旧局次/控制权响应继续丢弃。

无移动、无近期火力、未回血、未占目标持续6秒，标记无收益并提示执行者重选，同时请求指挥重评；不把健康守旗误判为罚站，不自动指定替代战术。
