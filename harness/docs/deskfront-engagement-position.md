# Deskfront 交战位置机制

目标是让单位按**真实武器射程、当前职责、地形和队友位置**选择交战位置，而不是为坦克、火箭筒等兵种分别写「向前走多少」的规则。`src/deskfront/world/engagement_profiles.json` 保存职责对应的射程区间；射程与溅射半径始终取本局引擎武器数据，不能从兵种名推断。

当前接线分两处：

- Godot 的 `engagement_position.gd` 给原生坦克挑候选炮位。它检查可走、路径、视线、预计转向后的发射点和友军安全，返回炮位或明确失败；`tactics.gd` 执行移动，武器系统决定能否开火。首要目标没有可用射位时，会依次试探其他已发现的敌人。采样、路径检查和重新规划都有上限，避免每帧全图搜索。
- 同一评估器也给带溅射武器、被分配为 `fire_support` 的小队士兵寻找局部射位。它只针对已发现且在射程内的目标，在当前位置周围最多移动 0.42 个世界单位；推进途中进入有效远程射位且真实射线畅通时，就通过现有意图执行器停下保持射位。路线受个人动作、避险和现有小队命令约束，无法找到射位时报告失败，而不暗中改派战略区域。
- “有可攻击目标”不等于“枪口畅通”。执行器维护射位前会调用引擎的真实发射点判定；被桌面物品挡住的目标仍会进入换位流程。
- 小队 JEV 的区域候选附上各成员的射程适配，以及已知敌人方向上相对于己方坦克的前后距离。JEV 选职责和区域路线，Godot 再验证逐兵路径、射界和最终动作。区域中心仅供比较，不是保证可用的火力点。无已知敌人时不臆造前后关系。

这不是意图执行器（IntentExecutor）。意图执行器仍只负责意图缓冲与执行状态机；战术选择属于模型和战术系统，引擎状态与回执是执行事实。

目前坦克与火箭筒兵已共用射位评估器，但执行入口不同：坦克原生导航可在较大范围内换炮位；小队火力兵仅作本区域内的短距离修正。步兵前出信息已送给 JEV，仍需在完整对局里验证其选路和存活表现；几何上位于坦克前方并不代表该位置安全。反坦克炮未部署，不属于本轮实战验证。
